## TL;DR

Seven incremental steps (A → G), each independently testable, each leaving the app in a working state. **One TestFlight build at the end of step C** for first real-device verification, **one more at step G** for handoff to Jean. Changes touch ~9 files, ~half of which are auto-generated by Capacitor or Xcode. Largest regression risk is the `parseTileUrl` extraction (step B) since it routes the existing passive flow through new code. Mitigated by keeping behaviour byte-for-byte identical and adding a console-log assertion path during dev. **MVP estimated total effort: 3–3.5 dev-days, requiring 2 TestFlight builds, with 7 explicit risks called out.**

### Step B — Refactor: extract `parseTileUrl` (≈ 0.25 day)

Goal: route the existing passive flow through a shared helper that the active flow will also use later. **Behaviour must be byte-for-byte identical.**

#### B.1 — Create the helper

New file `src/utils/parseTileUrl.js`:

```js
export function parseTileUrl(urlStr) {
  if (!urlStr) return null;
  let normalized = urlStr;
  if (!normalized.includes('://')) normalized = 'https://' + normalized;
  let url;
  try { url = new URL(normalized); } catch { return null; }
  const pathMatch = url.pathname.match(/^\/t\/(.+)$/);
  let raw = pathMatch ? decodeURIComponent(pathMatch[1]) : null;
  if (!raw) raw = url.searchParams.get('tile');
  if (!raw) return null;
  return raw.replace(/[:.]/g, '').toUpperCase();
}
```

**Note exact matching to existing logic** at [src/App.js:4346-4357](src/App.js:4346) and [src/App.js:5157-5169](src/App.js:5157):
- The `https://` prefix workaround for protocol-less URLs ✅
- The `/t/{uid}` path match ✅
- The `?tile=` query fallback ✅
- The colon/dot stripping + uppercase normalisation ✅

#### B.2 — Refactor passive UL listener at [src/App.js:4343-4364](src/App.js:4343)

Replace the body of the `appUrlOpen` listener with a call to `parseTileUrl(event.url)`. Keep the existing `console.log` lines for diagnostic continuity (the previous latency investigation referenced these). After:

```js
try { CapApp.addListener('appUrlOpen', (event) => {
  const urlStr = event.url || '';
  console.log('[TILE TAP] appUrlOpen: received URL =', urlStr);
  const tileUID = parseTileUrl(urlStr);
  if (tileUID) {
    console.log('[TILE TAP] appUrlOpen: extracted tile_uid =', tileUID);
    setDeepLinkTileUID(tileUID);
  } else {
    console.log('[TILE TAP] appUrlOpen: no tile UID in URL');
  }
}); } catch (e) { console.warn('[Capgo] appUrlOpen listener failed:', e); }
```

#### B.3 — Refactor cold-launch branch at [src/App.js:5157-5163](src/App.js:5157)

Replace the inline parsing with `parseTileUrl(window.location.href)`. The fallback to `?tile=` query already lives in the helper — local logic simplifies to:

```js

if (tileUID) {
  raw = tileUID;
  appState = 'cold-launch-url';
}
```

(`raw` is used downstream at line 5168-5170 for the same normalisation, which becomes a no-op since `parseTileUrl` already normalised. That's fine — idempotent.)

#### B.4 — Verify

- **Regression: passive tap.** Cold-launch URL still works (open https://app.ritualhabits.com.au?tile=TEST in mobile Safari → "Open in Ritual" prompt → app receives URL → tile UID logged). Banner-tap-via-NFC still works. Run `[TILE TAP] extracted tile_uid` log appears identically to before.
- **Edge cases the old code handled** that the helper must also handle:
  - `event.url` is empty/null → returns `null` cleanly
  - Malformed URL → caught by try/catch, returns `null`
  - URL with `tile=` query but `/t/X` is also somehow present → path takes precedence (existing behaviour preserved by the helper)

If `parseTileUrl` returns wrong UIDs OR returns `null` when it shouldn't, every Jean-family tap fails silently. **Christelle must do a passive-tap regression check on her own iPhone before this step is "done"** — at minimum: cold-launch tap ✅, warm-app tap ✅, banner-tap ✅.

### Step C — Active scan core (≈ 1 day)

Goal: end-to-end active scan flow working via a TEMPORARY debug button, NOT the final FAB. Confirms the plugin actually works on Ritual's hardware before investing in UI polish.

#### C.1 — Build `useNfcScanner` hook in `src/hooks/useNfcScanner.js`

Responsibilities:
- On mount: cache the result of the plugin's `isAvailable()` (or equivalent — confirm exact API name from `@capgo/capacitor-nfc` README during install). Expose as `available: boolean`.
- Expose `scan(): Promise<{ url?, cancelled?, timedOut?, error? }>`. Internally:
  - Start a `nfcEvent` listener that captures the first emitted record.
  - Call plugin's `startScanning({ alertMessage: 'Tap a Ritual tile', invalidateAfterFirstRead: true, iosSessionType: 'ndef' })`.
  - Wait for either: (a) the listener fires with a URL → resolve `{ url }`; (b) the plugin's promise resolves with `cancelled` / `timedOut` / `error` → resolve accordingly.
  - Always remove the listener before returning (memory hygiene).
- Track `scanning: boolean` for UI loading state.
- Track `lastError: string | null` for surfacing errors in the FAB.

#### C.2 — Add temporary debug button in `App.js`

A bare `<button onClick={runScan}>Test Scan</button>` placed inside the existing `RitualApp` JSX, e.g. just after the toast list at ~line 5310. `runScan` is:

```js
const runScan = async () => {
  const result = await scan();
  if (result?.url) {
    const tileUID = parseTileUrl(result.url);
    if (tileUID) setDeepLinkTileUID(tileUID);
    else addToast("That's not a Ritual tile", 'error');
  } else if (result?.cancelled) {
    // silent
  } else if (result?.timedOut) {
    addToast("Scan timed out — try again", 'info');
  } else if (result?.error) {
    addToast(result.error, 'error');
  }
};
```

### Step F — Polish: error states and one-time permission explainer (≈ 0.25 day)

Goal: handle edge cases that aren't blockers but matter for a TestFlight cohort.

#### F.1 — First-time NFC permission explainer

iOS shows the system permission prompt the very first time `NFCNDEFReaderSession.begin()` is called. Users have no warning. Add a one-time in-app sheet before the FIRST `scan()` call:

> **Allow NFC scanning?**
> iOS will ask you for permission to scan NFC tiles. Tap "Allow" so you can use Quick Log.
> [Cancel] [Continue]

Implementation: a localStorage flag `ritual_nfc_explainer_seen`. On first FAB tap, if flag absent, show the explainer. On Continue, set the flag, then call `scan()`. On Cancel, just set the flag (so it doesn't reappear) but don't scan.

#### F.2 — "NFC denied" recovery

If the user denied NFC permission previously, every `scan()` call will silently fail with `readerSessionInvalidationErrorSystemIsBusy` or similar. Detect this state in `useNfcScanner` and surface a toast: "NFC access denied. Open Settings to enable." Tap → opens `app-settings:` via Capacitor Browser plugin (already installed, [package.json:7](package.json:7)).

#### F.3 — Error toast styling

Confirm existing `addToast` ([src/App.js:4291](src/App.js:4291)) supports an `error` variant. If yes, use it. If not, add a basic one (it accepts `type` already at line 4291 — should just work).

**Regression scope:** Low. Additive; doesn't change existing flows.
**TestFlight build needed?** No.

## 7. Out of scope for MVP

**Explicitly NOT in this build:**

- ❌ App Intents / Siri / Lock Screen integration. Phase 2.
- ❌ Sequential auto-relaunch after a successful scan. Phase 2.
- ❌ "Log routine" guided multi-tap walkthrough. Phase 2.
- ❌ Custom Capacitor NFC plugin (only swap to this if step C.3 forces the pivot — not pre-emptively).
- ❌ Tile-quality experiments with premium credit-card-style NFC cards. Parallel hardware track, not gated by this work.
- ❌ Hardware-floor decisions for very old iPhones (iPhone 6, etc.). Wait for MVP results to inform.
- ❌ Telemetry / analytics on scan-success-rate, time-to-first-read, cancel-rate. Phase 3 polish if there's product signal we need.
- ❌ Android NFC. Android Capacitor uses different APIs and isn't on the Ritual roadmap.
- ❌ NFC tag *writing* (changing what a tile encodes). The Capgo plugin supports it, but we don't expose it.
- ❌ Refactoring the rest of `App.js` while we're touching it. Resist scope creep — this MVP touches only the existing tile-tap useEffect surface.
- ❌ Backwards-compat shims for the old `/t/{tileId}` URL format (if it ever appears). Existing parser handles both; no new work needed.
